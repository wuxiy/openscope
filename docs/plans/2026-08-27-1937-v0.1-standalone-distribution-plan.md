## Current Baseline

- 仓库仍处于 pre-code 阶段：没有 Maven 工程、Compose 发行版、示例应用、CLI 或产品级验证脚本。
- V0.1 的需求、技术 owner contract 和稳定验收清单已经建立；长期方向仍由两份根架构文档拥有。
- 2026-08-27 已冻结候选 release tag：Collector Contrib `0.159.0`、Prometheus `v3.14.0`、Loki `3.7.6`、Tempo `3.0.3`、Grafana `13.2.0`、OTel Java Agent `2.31.1`、Spring Boot `4.1.1`、Java `21`。
- 当前环境无法连通 Docker Registry，尚未取得各镜像 multi-arch manifest digest；这些 tag 只是候选 BOM，不是通过兼容性测试的 OpenScope BOM。
- `./tools/mission-driver.sh list | run demo` 只验证 AGE 流程脚手架，历史 demo 曾把外部命令失败 reconciliation 为 completed，不能作为产品实现或 V0.1 验收证据。
- 本地工作区是 macOS arm64，但用户指定完整实施验证必须在 `root@172.16.65.59` 执行；该开发机为 CentOS Stream 9 x86_64，具备 Java 21、Docker 29.5.3、Compose 5.1.4 和 Buildx 0.34.1。
- 开发机是共享主机，当前有 33 个运行容器；`3000`/`13000` 已占用，根盘剩余约 14 GiB，Docker Registry 直连与 Buildx manifest inspect 超时。V0.1 必须隔离 project/workdir、使用 Grafana `13001` 验证覆盖，并在 Phase 0 关闭镜像解析阻断。

## Goals

- 交付一份可重复启动的 standalone 发行版，使 Spring Boot 示例经 Java Agent 和 Collector 将 traces、metrics、logs 写入 Tempo、Prometheus、Loki，并在 Grafana 中可查询和双向关联。
- 交付固定 BOM、最小 CLI/doctor、Provisioning 资产、失败语义和机器可执行验收脚本。
- 以真实后端查询、敏感值 canary、重启与重复执行证据证明 V0.1，而不是以容器健康或文档存在代替运行结果。

## Non-Goals

- Central、Distributed、Kubernetes、Helm、HA、多租户、TLS/mTLS、OIDC。
- OpenScope Starter/autoconfigure/logback 自研库；V0.1 只用官方 Java Agent。
- stdout/filelog、Host Metrics、专项 Dashboard、Alert/SLO、Tail Sampling、Persistent Queue。
- 离线镜像包、备份、恢复、升级、政务/医疗生产合规认证。
- 为尚不存在的第二种后端预建 Backend Adapter 抽象。

## Infrastructure And Config Prereqs

- 开发机 SSH：`root@172.16.65.59`；只使用已知 host key、BatchMode 和关闭 agent forwarding 的自动化连接。
- Docker Engine/Compose 支持多架构 manifest inspect；第一阶段需要可审计地访问 Docker Hub/GHCR 或批准的镜像代理，Maven Central 已实测可达。
- Java 21；项目生成 Maven Wrapper 后只通过 `./mvnw` 构建。
- 默认 profile 使用 `127.0.0.1:3000/4317/4318`；开发机 profile 使用 `127.0.0.1:13001/4317/4318`，每次运行前重新检查端口。
- 远端工作目录 `/root/workspace/openscope-v0.1`、依赖目录 `/root/workspace/openscope-v0.1/dependencies`、Compose project `openscope-v01`；不得将依赖散落在 `/root` 或 `/root/workspace` 根层，也不得操作其他 project。根盘可用空间低于 10 GiB 或使用率达到 90% 时阻断启动，且不得自动清理共享 Docker 资源。
- `.env` 中必须设置非默认 Grafana 管理员密码；`.env` 和 Registry token 不进入 Git。
- `distribution/bom.yaml` 是版本唯一权威；digest 未齐全时不得执行第一次 Compose start。

## Execution Plan

### Phase 0 — Bootstrap And BOM Materialization

Status: planned
Targets: `pom.xml`, `.mvn/`, `mvnw`, `mvnw.cmd`, `distribution/bom.yaml`, `tools/resolve-bom.sh`, `tools/verify-v0.1.sh`, `tools/verify-v0.1-remote.sh`, `docs/context/project-context.md`
Skill: none

- Item Types: `Add | Decision | Proof`
- Prereqs: independent human draft review accepts this plan；官方 Registry 或批准的镜像代理具备可审计的 manifest 解析路径

- [ ] Add：建立 Java 21 Maven Wrapper 与最小聚合工程，先让真实 build/test 命令存在且失败可见。
- [ ] Add：实现 `tools/resolve-bom.sh`，只接受 owner contract 中的 exact tag，解析并记录 multi-arch manifest digest、来源、解析时间、amd64/arm64 子 manifest、SBOM，以及上游实际发布的 provenance/signature 验证结果。
- [ ] Decision：将候选 tag 物化为 `distribution/bom.yaml`；若任一 digest/架构失败，或上游声明存在的 provenance/signature 验证失败，则 Phase 0 保持未完成且不得写 Compose；上游未发布该材料时记录 unavailable。
  - Rationale：只锁 tag 不能抵抗重推；运行前冻结 digest 是发行可重复性的最低条件。
  - Alternatives Rejected：浮动 tag、只锁 major/minor、手填未经验证 digest。
  - Residual Risk：本阶段确认的是来源与架构，不代表五组件组合已经兼容。
- [ ] Add：建立 `tools/verify-v0.1.sh` 的 fail-closed 框架，未实现的检查必须失败，不得输出跳过后退出 0。
- [ ] Add：建立 `tools/verify-v0.1-remote.sh`，校验 host key、传输 payload revision/摘要、执行共享主机 preflight、限定 `/root/workspace/openscope-v0.1` + `openscope-v01` 作用域，将所有依赖归档在 `dependencies/`，并回收脱敏证据。
- [ ] Proof：在不拉取镜像、不创建目录的只读预检中记录远端 OS/arch/toolchain、现有端口、磁盘、Registry/Maven 连通性和非 OpenScope 容器基线。
- [ ] Proof：运行 `./mvnw -q verify`、`./tools/resolve-bom.sh --check`、`./tools/verify-docs.sh`，记录命令、退出码和 BOM 摘要。

Exit Criteria:

- [ ] 所有镜像以 `tag@sha256:digest` 固定，amd64/arm64 manifest、Java Agent SHA-256 和可获得的 upstream provenance 有机器证据。
- [ ] Maven Wrapper 与 V0.1 验证入口真实存在；未实现产品检查会明确失败。
- [ ] 远端 runner 的 dry-run 能证明 payload、命令作用域和共享主机保护规则，且不会修改开发机。
- [ ] `docs/context/project-context.md` 中的 build/static/test 命令与实际文件一致。
- [ ] owner contract、验收清单和 `docs/logs/` 已按实际 BOM 更新。

## Deferred But Adjudicated

### Central And Distributed Topologies

- Classification: `out-of-scope improvement`
- Why Not Blocking Closure: V0.1 的产品合同是 loopback single-host；跨网络认证、TLS/mTLS、多租户与 HA 是另一结果面。
- Reopen Trigger: V0.1 验收关闭后创建 V0.2 或独立拓扑需求。
- Successor Required: yes

### Starter And Custom Java Modules

- Classification: `out-of-scope improvement`
- Why Not Blocking Closure: V0.1 明确只验证官方 Java Agent；自研 SDK 会扩大兼容性和维护面。
- Reopen Trigger: standalone 三信号闭环稳定，且出现 Java Agent 无法满足的已验证需求。
- Successor Required: yes

### Offline, Backup And Upgrade

- Classification: `out-of-scope improvement`
- Why Not Blocking Closure: 这些能力需要独立的介质、回滚、隔离环境与兼容性合同。
- Reopen Trigger: 在线 standalone 发行版完成后进入离线/长期维护里程碑。
- Successor Required: yes

### HA, Multi-Tenancy And Extended Dashboards

- Classification: `out-of-scope improvement`
- Why Not Blocking Closure: 不属于首个单机闭环的必要证明。
- Reopen Trigger: Central/Distributed 需求被批准，或用户证据表明 Overview/Service 不足以支撑目标工作流。
- Successor Required: yes
