## Current Baseline

- V0.1 standalone implementation, BOM pins, five-component Compose topology, Java Agent sample, Grafana provisioning, CLI and historical amd64 runtime evidence exist.
- Local static verification passes, and historical integration evidence records two `25/25` runs, persistence, correlation and shared-host snapshots.
- The accepted claim is not currently defensible because AC-06/09/10/11/15/16 contain confirmed proof or implementation gaps:
  - redaction canary does not exercise response/body or Collector-side deletion on traces, metrics and logs;
  - Prometheus does not promote the resource attributes used by Dashboard metric queries;
  - `doctor` checks container existence and provisioned objects rather than the full health/OTLP/permission contract;
  - remote verification writes a sample log outside the owned workdir, can reuse a stale JAR and does not fail on Java Agent checksum mismatch;
  - the original plan, checklist, log and known-good baseline are textually inconsistent.
- These are confirmed defects or contract drift. None may be downgraded to follow-up.

## Goals

- Make AC-06/09/10/11/15/16 mechanically verifiable and fail-closed.
- Re-run the complete amd64 acceptance in the specified isolated remote environment with raw evidence tied to the current payload.
- Leave the original V0.1 plan, checklist, owner docs, dev log and known-good baseline textually consistent with the verified result.

## Non-Goals

- No component version or BOM policy changes.
- No Central/Distributed topology, TLS/mTLS, multi-tenancy, HA, offline packaging or arm64 real-run expansion.
- No replacement of the Java Agent with an OpenScope SDK or Starter.
- No weakening of the application-side non-capture rule or loopback-only standalone trust boundary.
