## 验收过程遇到的问题与修复（均可复现，已固化进脚本）

1. **compose digest 双重前缀**：`@sha256:${OPEN_SCOPE_BOM_*_DIGEST}` 与 env 中 `sha256:` 前缀叠加 → 修 compose 模板（提交 `e1f1023`）。
2. **Tempo 查询时序**：vParquet search 索引有可见延迟，`sleep 5` 后单次查询误报"无 trace" → verify 脚本加轮询（最多 10×3s），提交 `5c86ea5`。
3. **D3 失败证据聚合**：Tempo search 不保证按时间排序，`traces[0]` 常是 200 trace → 改为遍历全部 traces 寻找 500/ERROR span，提交 `017b331`。
4. **D7 TID 匹配**：search 命中的首个 trace 不一定有对应日志 → 遍历候选 trace 找在 Loki 有日志的，提交 `5c86ea5`。
5. **service.namespace 假阴性**：`-Dotel.service.namespace` 不是官方 JVM 属性（agent 不认），旧版本靠旧进程 resource.attributes 里的巧合值 PASS → 移入 `-Dotel.resource.attributes=...,service.namespace=openscope-demo`，提交 `c0f5117`。
6. **target_info 60s 窗口**：OTel Java SDK 默认 metrics 导出周期 60s，verify 查询窗口落在首次导出前 → 样本启动加 `-Dotel.metric.export.interval=5000`，提交后 `checks=25/25` 全绿。
7. **远端 ssh 自伤**：`pkill -f verify-v0.1` 匹配到承载命令的 bash 自身导致 exit 255 → 后续只用精确 `-x` 名匹配进程。
