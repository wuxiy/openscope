## Multi-Dimensional Review

### Product And Scope

- 一条结果面：本机 standalone 三信号闭环。
- 不把 pre-release 写成生产就绪；Central、离线、备份升级和自研 Starter 有明确 successor trigger。
- Primary flow、失败路径和人工操作足以让实施者不猜产品行为。

### Architecture And Maintainability

- 应用保持 OTel/OTLP backend-neutral；Collector 与唯一官方后端组合边界清晰。
- 不为第二后端预建抽象；先以真实集成稳定第一条路径。
- exact BOM、Provisioning、CLI/doctor 和可重复验证构成可持续升级基础；单组件升级必须重跑全验收。

### Security And Operations

- V0.1 明确为 loopback single-host，不把无 TLS/认证的信任模型外推到 Central/Distributed。
- 默认不采集敏感值 + Collector 已知 key 删除 + canary 后端检索形成可验证防线。
- 运行健康、数据存在、关联行为、失败恢复分别验证，避免健康检查假绿。

### Proof Quality

- AC 与 checklist 覆盖 BOM、配置、网络、三信号、安全、Grafana、CLI、持久化和重复执行。
- 当前所有运行项保持 unchecked；没有把未执行、manifest-only 或人工点验写成自动通过。
- Docker Registry 本轮不可达，因此不记录推测 digest；这是 Phase 0 non-degradable blocker。
- 复核上游契约后，owner contract 明确要求实际证明 Java Agent Logback instrumentation scope，并把 Loki index-label 映射归属到 `limits_config.otlp_config`，避免依赖隐式默认值。

## Draft Plan Self-Review

- 阶段依赖从 BOM → runtime → signal → UI → failure/repeatability → full acceptance 单向推进。
- 每阶段包含 targets、skill、item types、proof 和 owner-doc/dev-log exit criteria。
